## 5. 冻结的一期产品范围

- Resource 内独立 vm 领域，复用既有分层和 composition root；KubeVirt/CDI/CSI/KCN 执行原生能力，不自建虚拟化、网络 binding 或 CSI 编排控制器。
- Linux、Windows 各至少一个正式固定版本；保留 qcow2/raw 创建、ISO 手工安装、介质挂载/弹出、原生启动顺序与真实浏览器 VNC。
- 用户后续授权的可选账户初始化仅用于已实测、绑定 source UID/hash 的 NoCloud Linux DISK_IMAGE；具体边界以[S05.1](../specs/vm-mvp.md#s051-linux-镜像的可选账户初始化)及[C03.1](../contracts/vm-v1.md#c031-用户输入字段)为准。
- VM 自有系统盘和数据盘固定 Block/RWO，十进制正整数 GB、步长 1 GB；ISO、驱动与 TPM/UEFI backend state 按各自原生合同处理。
- 一块系统盘、零到多块数据盘；独立 DV、不使用 dataVolumeTemplates；稳定逻辑盘身份、冷/热挂卸、卸载保盘、精确删除。
- 使用现有 compute 目录，显式 VIRTUAL_MACHINE usage；CPU/内存值和来源按合同冻结，Start/重放不重新解析。业务前端的 GPU 规格筛选留给其 owner；本任务不新增 VM 专属后端 GPU 禁令，不实现 VM GPU 执行。
- 本期不接 CPU/内存/磁盘余额检查、占扣退额；保留授权、套餐资格、持久 operation 与投递，不破坏现有容器 GPU 原账。
- 容器与 VM 共用 Resource owner 和一个聚合 adapter，按正式 action/codec/usage/resource kind 分派；不把 Resource owner 默认当容器，不放开旧禁用版本。
- Manual 与原生 Start/Stop/Restart/ForceStop；Restart 保存 old_vmi_uid、未知结果先观察，不盲重发，不新增运行代次系统。
- Multus 主网络 + 原生 bridge + KCN，单租户主网卡、动态 IP、VM consumer v3；保留旧 Network v1/v2，Stop 保留 Attachment，最终删除再 Release。
- 在线/离线原生磁盘快照、必要卷完整性与一致性展示、关机恢复到原 VM；不提供可恢复 RAM 状态。遵守包内五种盘集合、新旧卷映射、恢复后 hotpluggable 与清理规则。
- VM 最终删除包括当前/卸载/被替换盘、介质副本、backend state、快照及网络占用，保护共享源、NAD 和其他租户。

- 每种 OS 至少两块 Block 数据盘，冷/热挂卸、卸载后再挂、重启后 marker 保留；不擅自启动停止态 VM。当前环境沿用 ani-block Immediate，WFFC 专用 LIVE 按上述用户修订记不适用/未覆盖，不新增环境来补验，既有 WFFC 代码/PG/BOUNDARY 历史保留。
- 双系统在线/离线快照各完成恢复、显式启动和盘数据读回；必要卷被排除不冒充完整；五种盘集合、新映射及三个恢复 checkpoint 经进程退出恢复，旧卷清理失败不重复 Restore/写回旧 DV。

## 9. 恢复、清理与阻塞处理

- 每张卡保存足以恢复的 commit/dirty 摘要、实际 host、关键命令/退出码、对象 UID、当前原生步骤和剩余清理引用；正常完成后继续下一卡，不复制多套过程日志。
- 外部前置缺失时具体标明受影响卡，完成其他可独立工作。必须询问的镜像/维护/发布批准使用明确问题，等待期间不把沉默当同意。
- 未知原生写入先按持久身份查证，不盲重发非幂等动作、不换名字补造资源；删除有身份栅栏、不能接管同名新 UID。
- 失败后按已批准恢复方案恢复本任务变更；不能擅自修改 KCN、账本、共享安全策略或清理其他任务。必要人工处理写清具体对象、影响和下一步。
- 用产品入口优先清理任务资源，核对原生对象和底层回收，恢复临时代理、测试 RBAC、授权范围内的临时配置；用户准备的镜像及共享基础组件保留。永久运行时修正按获批方案保留或回退，不自作主张。
- 上下文不足或新任务恢复时，从唯一状态、固定来源与对象身份继续；不从头重跑已过关卡，也不因时间/token 接近上限宣告完成。
